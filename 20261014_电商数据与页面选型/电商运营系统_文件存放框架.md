# 电商运营系统文件存放框架

日期：2026-11-05。状态：用户确认，已实施。此标准用于今后新建项目，其它已有项目不追溯调整。

建议采用一个应用目录、前后端分开、文档与运行数据各归其位的结构。根目录默认只保留3个常驻文件，不再放Python程序、接口文档、迁移记录或多套启动脚本。

审阅调整：不设置维护记录目录，不额外保留示例配置。`config/local/`存放本机直接使用的真实配置，已有账号和数据库口令原样保留；尚未配置的API密钥不编造。根目录只保留README、启动入口和.gitignore。

本方案沿用现有FastAPI、MySQL、Vue技术栈，目的只在于把当前项目放得清楚、便于运行与维护。

## 一、系统目录入口

```text
电商运营系统/
├─ README.md                  项目入口：如何启动、配置、查看文档
├─ 启动系统.cmd               唯一双击启动入口，只调用scripts中的启动脚本
├─ .gitignore                 本地配置、运行数据、依赖及缓存的忽略规则
│
├─ backend/                   后端程序与后端测试
├─ frontend/                  Vue前端程序与前端构建配置
├─ config/                    本机配置、登录信息
├─ docs/                      必要接口说明
├─ scripts/                   启动、数据库安装与迁移工具
├─ runtime/                   数据库、上传批次、模型、日志及临时文件
└─ vendor/                    本机便携MySQL和临时内置Python依赖
```

以后找文件按用途进入对应目录：启动看根入口，修改功能看backend/frontend，查看说明看docs，查登录账号看config，查日志和数据看runtime。

### 旧版实现单独处理

`server.py`、`web/`、`启动看板.cmd`、`启动看板.ps1`是一套旧版看板实现，建议归档到：

```text
学校项目/03_测试与验证/历史实现/旧版看板/
├─ server.py
├─ web/
├─ 启动看板.cmd
└─ 启动看板.ps1
```

不能直接搬走就算完成：当前程序还保留原生页面回退，`manage.py`的旧`serve`命令也会调用`server.py`。以后真正整理时，必须先统一正式启动链、明确旧回退是否停用，再归档并修正引用。本次已统一正式启动链，旧代码仅作为归档及相关历史测试依赖保留。

`runtime/initial_admin.txt`是原始初始化凭据，和后来新增的登录配置用途有重叠。整理时应统一凭据生成/查阅入口，保留能登录的有效记录，再处理旧记录；不能直接覆盖或擅自重置账号。

## 五、以后新文件的存放规则

1. 业务Python代码放`backend/app/`，命令行工具放`backend/cli.py`或` scripts/`，不要继续放应用根目录。
2. 前端功能代码放`frontend/src/`，构建生成的`dist`不手改。
3. 必要接口说明放`docs/`，不另设维护记录目录。一次实验的报告、脚本和结果放外层同一个实验包。
4. 真实登录口令、数据库连接和已有API密钥放`config/local/`，本机可以直接使用；不再额外放示例配置文件。
5. 运行产生的数据库、模型、上传文件、日志与临时文件只写`runtime/`的约定位置。
6. 自动化测试代码放`backend/tests/`；某次验收的证据集中放外层`03_测试与验证/`相应包，并写清代码版本和复现入口。
7. 根README只做入口说明，不再持续新增“最终说明”“迁移说明”“新计划”等并列根文档。

## 六、方案确定后如何实际整理

建议分两步实施，避免一次搬动程序、数据库和历史原料。

**第一步：收拢文档、脚本和旧版入口。**建立文件去向清单，确认每个文件是有效实现、历史依据还是自动生成物；文档进入docs，本地配置进入config，启动脚本集中到scripts，核对旧看板回退引用后再归档。原料和运行数据库优先保持当前路径。

**第二步：统一后端代码包。**把当前api和services移入backend/app，调整Python导入、启动入口和统一项目根路径；迁移现有测试代码并修正复现路径。前端目录不再重新拆分。

实际整理必须同步核对：

- 根目录cmd仍能直接启动MySQL与后端；前端dist仍由FastAPI正确提供。
- Python导入、配置加载、模型输出和上传批次路径正确；不能依赖某次终端恰好所在的目录。
- 便携MySQL的basedir、datadir、日志和临时目录配置正确。若确需移动数据目录，先正常停库并保留可恢复副本，不能移动正在运行的库。
- 账号能正常登录，已有数据、库存、任务和模型仍能读回。
- 预测、补货流程及必要回归通过；目录整理本身不触发重新调参或改写旧实验结论。
- 文档、脚本、总索引与配置中的引用同步更新。最终以逐文件清单核对，不以“文件已经移动”作为验收完成。

已按该框架整理。根目录只保留README.md、启动系统.cmd、.gitignore；登录信息见config/local/登录配置.ini，API说明见docs/API契约.md。运行数据、账号和既有模型保留原内容。
