# 单模型预测与可操作补货演示

目标：业务系统仅提供一个预测模型；补货页面直接有可核对的商品、模拟库存、在途和流水，并支持确认补货及到货入库。

预测主指标为2011-08-16至10-14目标期完整7天窗口WAPE，辅看MAE与偏差。比较已部署组合与仅基于起点以前历史的异常峰值稳健化：对周季节分量输入及输出使用同星期近期中位数与MAD上界。固定比较3、4、6倍MAD三个系数；如验证无改善则保留原组合，不新增前端选项。后续2011-10-15至12-09只作已观察历史的回溯核对，不称新盲测；末端大单保留正式评分。不得以更换回测区间宣称模型提升。

补货验收：12个真实商品编号和名称、按近28天历史销量生成日需求参考、模拟初始库存与流水独立标识；缺货/充足/在途覆盖/晚到在途均有样例。重复载入不重复记账、不覆盖用户后续修改；确认补货登记在途、到货后余额和流水同步。

专用脚本与运行证据在本包，生产代码保留系统目录。本轮由Codex实施：上轮Claude Code CLI权限阻塞，依技能回退约定未重复启动受阻写任务。

## 完成结果

业务页面、预测/回测接口、AI预测工具及本地预测入口统一使用一个`robust_blend`流程，版本`daily-v3-robust-blend-mad3`；不再接收模型选择字段。旧实验算法仅保留用于研究复现，不作为业务选项。图表只显示部署预测与实际，基准留在离线验收证据与导出中。

| 同口径比较 | 原部署组合WAPE | 本次单模型WAPE | 样本 |
|---|---:|---:|---|
| 验证目标期08-16至10-14 | 33.75% | 31.84% | 54完整起点，378条 |
| 已观察后续目标期10-15至12-09 | 20.60% | 20.05% | 50完整起点，350条 |
| 页面默认起点11-05至12-02 | 19.22% | 18.67% | 同样28完整起点，196条 |
| 原末端部分窗口12-03至12-09 | 46.06% | 46.91% | 21条，0完整起点 |

规则在每个起点之前最近182天内按星期几拟合，中位数加3倍MAD、且不少于1.5倍中位数构成峰值延续上界；用于周季节分量及最终输出，不修改训练原始明细或评分实际值。参数仅按验证WAPE选择。后续期是反复观察过的历史回溯，不是新盲测；总体低估偏差由-5.44%变为-7.94%，突发大单仍然难以预测，不能宣称解决了所有尖峰。

原数据末日预测未来7天合计由272727件变为197343件，说明偶发大单的后续放大已收敛；这些日期没有实际值，不能声称新预测已经更准确。结果见`results.json`及逐条CSV。

## 实际补货数据与操作

- MySQL原始批次已创建`demo-original`持久化场景，12个真实商品编号与名称，日需求参考2011-11-12至12-09平均记录销量并向上取整。筛选至少8个有销售记录日的商品，避免把一次性大单当作常规补货需求。
- 初次载入含27条模拟出入库流水、9条采购记录（6笔运输中、3笔已入库），6个商品待补，建议合计9038件。库存、采购及流水均为模拟设定。
- 页面实际完成商品20668的1232件确认补货与到货入库：确认时库存308不变、有效在途1232；到货后库存1540、有效在途0、建议0。
- 当前保留演示操作后的状态：12个商品、28条流水、10条采购记录（6笔运输中）、5个待补商品、合计7806件；见`ui_flow_results.json`。点击“载入演示数据”不会清空这些操作，也不会重复生成流水。
- 库存概览前置，表单及参数编辑收进展开区；无需补货的行禁用确认按钮；补货、到货和出入库均会刷新余额、在途与建议量。操作去重标识由系统生成，用户无需填写。

## 页面与接口

- 新增`POST /api/inventory/demo`，显式载入或打开当前批次的演示场景；不会在查询请求里偷偷写数据。
- 新增`GET /api/forecast/latest`，恢复当前批次、当前部署版本最近成功的预测与回测；旧版本任务不会冒充新结果。
- 预测和回测各自跟踪任务，按钮在任务结束后恢复，避免重复提交或互相中断。预测已保存7天结果，回测已保存28完整起点结果。
- 修正AI简报未传递商品/国家筛选；修复前端类型错误及窄窗口导航拥挤。前端源代码和`dist`均已更新。
