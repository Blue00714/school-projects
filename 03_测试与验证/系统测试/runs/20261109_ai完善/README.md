# AI 问答与真实接口验证（2026-11-09）

## 结果

智谱接口 `glm-4.6v` 实际返回 HTTP 200；在 8777 本机系统登录后，以“近期经营情况”发起问答，返回 `status=ok`、`llm_used=true`，工具包含历史看板、已保存的全店预测和回测、模拟库存。模型区分了历史实际、历史预测、回测和模拟库存。样例问题的历史看板为 2011-11-10 至 2011-12-09，销量 851403 件、销售额 1694068.71 GBP、订单 2913 笔，与工具摘要一致。样例只验证当次输出，不能保证所有问题或所有数字正确。

当前批次数据末日为 2011-12-09，近期按批次末日计算。当前最近保存的预测起点为 2011-07-06，不能说成基于批次末日的未来预测；已有回测起点为 2011-11-05 至 2011-12-02。系统没有真实库存数据。

最初密钥认证返回 401，更换后成功。通过代理时多次出现 TLS EOF；三次直连返回 200，两次代理访问返回 EOF。本机应用配置增加对智谱域名的代理绕过；其后仍出现两次 DNS 失败，后一次从系统接口调用成功。因此网络仍可能波动，失败会如实显示。

## 改动与验证

- 综合问题按当前批次查询历史汇总，并读取已保存全店预测、回测及模拟库存；不触发预测训练或修改库存。局部问题继续只查询有关工具。向模型传递数据不是训练或微调；长列表设置上限并声明截取，不再截断 JSON。发送前移除订单客户 ID。
- 对销量与订单组合问题同时提供两项工具；商品、国家筛选作用于历史看板。页面明确提示模型回答应对照工具结果核验。
- 真实链路：登录后通过 `/api/ai/ask` 成功返回综合回答；另有近期销量、订单问答成功。失败路径也实测明确报错，保留本地结果。请求会产生系统 AI 问答运行记录。
- 四项上下文单元测试通过；隔离 AI API 套件 6 项通过（含 30 题规则样例）：[日志](../20261109_regression/ai_context_api.log)。套件在客户 ID 脱敏的最终小改动之前运行；最终脱敏有单独单元测试。前端类型检查和构建通过。
- 代码实现：尝试官方 Claude Code MCP 终端启动 CLI，长期无输出且未产出代码，终止确认后由 Codex 完成。

复现：在系统目录执行 `python -m unittest discover -s backend/tests/services -p test_ai_context.py -v`（将 `backend` 和本机 `vendor/python-packages` 放入 PYTHONPATH）；API 测试运行 `python backend/tests/api/run_api_tests.py --pattern test_ai.py --out ai_context_api.log`。真实调用依赖本机 API 配置、网络、智谱账户权限和当前批次，产生 API 用量。
